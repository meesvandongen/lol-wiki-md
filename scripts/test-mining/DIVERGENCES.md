# Test-mining divergence report

Generated by mining the live wiki corpus (`export_out/`, 597 entities + 3,310
transcluded template/module pages) and differential-testing the converter
against the wiki's own rendered HTML (`api.php?action=parse`). Reproduce with
the scripts in this directory (see `README.md`).

Method: every snippet below was rendered on the wiki (cached under the
gitignored `validation_reports/test-mining/render_cache.json`) and expanded
through the converter (`expand_inline_templates`). Pure value/parser-function
templates are
context-independent, so their standalone wiki render IS authoritative ground
truth. Templates whose level count depends on champion context (`ap`/`pp` with
implicit level counts) are NOT reliably comparable standalone and are excluded.

## Corpus coverage (PASS)

The full real corpus converts cleanly with **zero hard errors**. Against the
complete wiki download (21,831 files, 8,416 categories, 19,352 source pages):

- champions: 172/172
- items: 594/594
- runes: 77/77

(The earlier targeted export — all champions/items/runes from the data modules
plus transclusions — was 170/305/76; the full download adds Wild Rift variants
and items outside the main `ItemData` module, all of which also convert clean.)

So the fail-fast template registry recognizes every template actually reached
on the convertible champion/item/rune surface. The gaps below are reached only
inside template *definition* bodies or are silent (wrong-but-not-erroring)
rather than hard failures — which is exactly the dangerous, invisible class
AGENTS.md flags.

These are context-independent and unambiguous. Each is encoded as an
`#[ignore]`d test in `tests/template_combinations.rs` (module
`known_divergences`) asserting the wiki-correct value, so they are runnable on
demand (`cargo test -- --ignored`) and will pass once the handler is fixed.

## Intentional contract differences (NOT bugs)

The converter renders a lossless *text* contract where the wiki renders
icons/colored spans/tooltips. These are by design (see `STYLE.md`) and are
locked in as characterization tests, not differential tests:

| Input | Wiki (plain-stripped) | Converter | Note |
|-------|-----------------------|-----------|------|
| `{{gold\|500}}` | `500` (+ gold icon) | `500 gold` | icon → word |
| `{{ft\|a\|b}}` | `「 a 」「 b 」` (one side shown live) | `a *(equivalently: b)*` | documented flip-text normalization |
| `{{sbc\|small caps}}` | `small caps` (CSS small-caps) | `**SMALL CAPS**` | small-caps → bold uppercase |
| `{{rd\|85\|65}}` | `( 85 / 65)` | `85 (melee) / 65 (ranged)` | melee/ranged labels made explicit |
| `{{color\|yellow\|'''Steal'''}}` | `Steal` | `'''Steal'''` | color dropped; bold markup kept for the markdown layer |
| `{{ci\|Akshan\|'s}}` | `'s` (name is icon) | `Akshan's` | name text preserved |

(`{{times}}` and `{{Divided by}}` were previously listed here but are now in the
table above: fetching their template sources showed the converter is wrong, not
making a stylistic choice.)

## Context-dependent (excluded from differential tests)

Standalone wiki renders of these differ from in-context because `ap`/`pp`
infer their level count from champion context (defaulting to ability ranks ≈6
standalone). The existing converter unit tests for the `then`-segment forms
were validated in-context by the original authors and are left untouched.

- `{{ap|<7+ explicit values>}}` — standalone wiki caps display at 6 ranks.
- `{{pp|N; then +k*x ...}}` cumulative totals and bare `then` — level count
  differs standalone vs in-context (e.g. standalone `{{pp|0; then +5*x}}`
  renders `0 – 85`, but the converter deliberately leaves a bare uncounted
  `then` raw; see the existing `pp_bare_then_without_count_is_left_raw` test).
