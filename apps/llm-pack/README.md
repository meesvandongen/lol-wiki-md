# @lol-wiki/llm-pack

Compiles the pipeline's generated Markdown (`generated/markdown`) into an
**LLM-native knowledge pack**: structured JSON datasets, retrieval-ready
chunks, a token-compact roster digest, an `llms.txt` entry point, and a
Model Context Protocol server — so any LLM building programs about League of
Legends can ground itself in the wiki instead of model memory.

## Why this shape

LLMs consume the wiki in three distinct modes, and the pack serves each one:

| Need | Artifact | Cost |
|------|----------|------|
| Ground names, roles, base stats for the whole roster | `digest.md` | one line per entity |
| Exact mechanics text for one ability/item/patch | `chunks.jsonl` via stable ID or BM25 search | one section |
| Machine-readable numbers for program logic | `data/{champions,items,runes}.json` | structured fields |

The MCP server wraps all three behind tools, so agent frameworks get the
wiki as a queryable capability rather than a context-window dump.

## Design principles

- **Zero dependencies.** Node standard library only — no SDK, no embedding
  model, no API key, no index format to migrate. Search is plain BM25 built
  in-memory at load time. There is nothing to update, ever; that is the
  maintenance story.
- **Verbatim values.** Game values stay strings exactly as the wiki renders
  them (`0.651`, `14 / 12 / 10 / 8 / 6`, `(+ 60 / 67.5 / 75 / 82.5 / 90% AD)`).
  Nothing is computed, rounded, or inferred — per the repo's information
  integrity rules in `AGENTS.md`.
- **Lossless by construction.** Structured extraction only lifts the
  converter's stable section conventions; any section it does not model is
  preserved verbatim under the entity's `sections` map, and `chunks.jsonl`
  always carries every page's full text. New wiki sections degrade to
  "unstructured but present", never to "silently dropped".
- **Stable, structural IDs.** Chunk IDs like
  `champions/aatrox#abilities/q-the-darkin-blade` are derived from the
  wiki's own structure, so they survive rebuilds and only change when the
  wiki itself changes. `manifest.json` carries a content hash over source
  files so consumers can detect updates cheaply.

## Usage

From the repo root (after `npm run convert` has produced `generated/markdown`):

```sh
npm run llm:build                 # writes generated/llm-pack/
npm run llm:search -- "aatrox q sweetspot"
npm run llm:mcp                   # start the MCP server on stdio
```

Or directly:

```sh
node apps/llm-pack/src/cli.mjs build  [--input DIR] [--output DIR]
node apps/llm-pack/src/cli.mjs search <query> [--category champions|items|runes] [--limit N]
node apps/llm-pack/src/cli.mjs show   <chunk-id>
node apps/llm-pack/src/cli.mjs entity <category> <name>
node apps/llm-pack/src/cli.mjs list   [category]
```

### MCP client configuration

```json
{
  "mcpServers": {
    "lol-wiki": {
      "command": "node",
      "args": ["/path/to/lol-wiki-md/apps/llm-pack/src/mcp-server.mjs"],
      "env": { "LLM_PACK_ROOT": "/path/to/lol-wiki-md/generated/llm-pack" }
    }
  }
}
```

Tools exposed: `search_wiki`, `get_chunk`, `get_page`, `get_entity`,
`list_entities`, `get_digest`, `get_manifest`. The server loads the pack
once at startup; rebuild the pack and restart to pick up new content.

## Pack layout (`generated/llm-pack/`)

- `manifest.json` — build metadata, per-source SHA-256 hashes, counts, and a
  content hash that excludes timestamps (identical inputs hash identically)
- `llms.txt` — llms.txt-convention entry point describing the pack
- `digest.md` — one-line-per-entity roster with verbatim base values
- `data/champions.json` — overview, base/growth stats, advanced stats,
  per-mode special statistics, abilities (attributes, description, effects,
  details, notes), validation notes, plus unmodeled sections verbatim
- `data/items.json` — overview, stats, build tree, similar items, notes,
  patch history, validation, plus unmodeled sections verbatim
- `data/runes.json` — overview, description, notes, patch history,
  validation, plus unmodeled sections verbatim
- `chunks.jsonl` — one JSON object per section chunk:
  `{ id, category, entity, headingPath, text, tokensEst }`

## Testing

```sh
npm test --workspace @lol-wiki/llm-pack
```

Tests run against fixtures generated by the Rust converter from its own
`mini_export` test fixture (Aatrox, Infinity Edge, Electrocute), and cover
extraction, chunk losslessness and ID stability, BM25 ranking, the
end-to-end build (including verbatim number round-trips and content-hash
determinism), and a spawned-process MCP handshake/tool-call session.
To refresh the fixtures after converter output changes:

```sh
cargo run -p lol_wiki_md --bin convert -- \
  --wiki-root ./apps/converter/tests/fixtures/mini_export \
  --output ./test_output/llm-pack-fixtures --champion Aatrox
# repeat with --item "Infinity Edge" and --rune Electrocute, then copy the
# .md files into apps/llm-pack/tests/fixtures/sample-markdown/
```
